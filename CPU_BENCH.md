# Сравнение машин на Python

`cpu_bench.py` работает на Python 3.8+ без сторонних библиотек, на macOS,
Windows и Linux. Включает шесть вычислительных заданий:

| Тест | Работа | Один шаг |
| --- | --- | --- |
| `pi` | Численное интегрирование для вычисления π | Одна точка интегрирования |
| `integer` | 32-битный xorshift | Три сдвига и XOR с ограничением разрядности |
| `primes` | Поиск простых чисел перебором делителей | Один нечётный кандидат |
| `math` | `sqrt`, `sin`, `log1p` и суммирование | Один набор из трёх функций |
| `generate` | Генерация списка случайных целых, как в `smg3bench.py` | Одно число |
| `sort` | Сортировка заново подготовленного случайного списка | Одно число |

Это сравнение **Python на конкретных машинах**: процессор, интерпретатор,
математическая библиотека, ОС и настройки питания влияют на результат.
Изолировать производительность процессора от остальной системы таким тестом нельзя.
Тест не измеряет FLOPS, диск, GPU или ускорение векторных инструкций.
`generate` и `sort` дополнительно зависят от выделения памяти, кэшей и RAM;
это не отдельное измерение пропускной способности памяти.
Шаги разных заданий имеют разную стоимость: сравнивайте один и тот же тест
между машинами. Общего искусственного балла нет.

## Запуск

Используйте один и тот же файл скрипта и, насколько возможно, одинаковую
64-битную версию CPython, включая patch-версию, на всех компьютерах.
Не смешивайте CPython/PyPy, JIT/free-threaded и обычные сборки.
Даже одинаковые версии могут иметь разные оптимизации сборки; сведения о
сборке и компиляторе попадут в JSON.

На каждой машине достаточно одной команды из папки проекта:

```bash
python3 cpu_bench.py
```

Скрипт сам определяет модель CPU, доступные логические CPU, общий объём и
оценку доступной RAM. Запускает все тесты по 5 раз и сохраняет отчёт в
`bench_results/<процессор>.json`. Повторный запуск перезаписывает этот файл.
Например, для Apple M4 имя будет `bench_results/Apple_M4.json`.
На Windows вместо
`python3` обычно используется `python` или `py -3`. Для работы теста не нужны
AVX или сторонние пакеты; сам интерпретатор должен поддерживать старый процессор.

По умолчанию: все шесть тестов, **5 измерений каждого**, минимум один прогрев,
режим `single` с одним дочерним процессом, затем `multi` с автоматически
выбранным числом процессов. Обычно это все доступные логические CPU;
при нехватке RAM число процессов уменьшается. В `multi` выполняются только
`pi`, `integer`, `primes`, `math`.
Большие списки обрабатываются только в `single`, чтобы не создавать копию
из 10 миллионов чисел в каждом из 24 процессов. Прогон обычно занимает
несколько минут; длительность зависит от машины и фоновой нагрузки.

Для четырёх арифметических тестов число блоков подбирается отдельно для каждого теста и режима, чтобы замер
занимал примерно секунду. Внутри серии из пяти измерений число блоков
фиксировано. Сравнивается работа в секунду, поэтому разное число блоков на
разных машинах допустимо. Каждый блок выполняет одинаковую работу с теми же
данными; входные числа не растут с длительностью теста.

## Генерация и сортировка из smg3bench

`generate` создаёт список до **10 000 000** целых от 0 до 999999999999999999
циклом с `randint`, как исходный `smg3bench.py`. Каждый раз используется
локальный генератор `random.Random(42)`. При одной версии Python входные
данные воспроизводятся на всех машинах.

`sort` перед каждым прогревом и замером заново генерирует такой же
неотсортированный список. Генерация не входит во время сортировки.
Проверка результата и освобождение списка не входят во время обоих тестов.
У `sort` дополнительно проверяются порядок, число элементов и контрольные
суммы до и после сортировки. В JSON возвращается только короткая сигнатура,
сам список между процессами не передаётся.

Каждый замер этих тестов обрабатывает ровно один список, без калибровки по
`--seconds`: большой список может обрабатываться дольше секунды. Прогрев и
5 измерений сохраняются, как у остальных тестов. Медиана времени относится
к одному списку указанного размера. Время исходного `smg3bench.py` включало
генерацию и сортировку вместе, поэтому с отдельной строкой `sort` его сравнивать нельзя.

Только эти два теста:

```bash
python3 cpu_bench.py --mode single --tests generate sort --label MacM4
```

По умолчанию объём выбирается автоматически: 10 миллионов, 1 миллион,
100 тысяч или 10 тысяч чисел. Бюджет ограничен 1/8 всей RAM и 1/4 доступной
RAM, с запасом 32 MiB на рабочий процесс и оценкой 64 байта на элемент.
Это осторожная оценка, а не гарантия отсутствия подкачки при изменении нагрузки.
Если определить RAM не удалось, выбирается 100 тысяч чисел.
Для multi резервируется половина доступной памяти: 64 MiB на управление и
64 MiB на каждый рабочий процесс. `--workers` задаёт число процессов вручную.

Для одинакового объёма на всех машинах его можно задать явно:

```bash
python3 cpu_bench.py --list-size 1000000
```

Для сопоставления используйте одинаковый `--list-size` на всех машинах:
сортировка не масштабируется линейно по числу элементов. Команда `--compare`
пометит строки с разными размерами списков как несопоставимые и пропустит
отношение их скоростей, продолжив сравнивать остальные тесты.
В 64-битном CPython список из 10 миллионов таких чисел требует порядка
400 МБ на числа и ссылки; с запасом списка, сортировкой и аллокатором расход
будет выше. Закройте приложения, занимающие память, или уменьшите размер
на всех машинах, чтобы подкачка не определяла результат.
`--mode multi --tests generate sort` завершается с пояснением, поскольку
эти тесты поддерживают только один процесс.

Для отдельного сравнения SMT на Ryzen:

```bash
python3 cpu_bench.py --mode multi --workers 12 --label Ryzen12 --output bench_results/ryzen-12.json
python3 cpu_bench.py --mode multi --workers 24 --label Ryzen24 --output bench_results/ryzen-24.json
```

Для более длинных измерений и увеличенного числа повторений:

```bash
python3 cpu_bench.py --seconds 2 --repeats 10
```

Все параметры необязательны. Для ручных настроек доступны `--label MacM4`,
`--output bench_results/mac.json`, `--mode single`, `--tests pi integer`,
`--list-size 1000000` и `--warmups 2`.
Без `--output` используется имя процессора (либо явно заданный `--label`)
в папке `bench_results/` относительно текущей папки. Новый отчёт перезаписывает
существующий файл после завершения тестов.

Память определяется штатными средствами ОС: `sysctl`/`vm_stat` на macOS,
[`/proc/meminfo`](https://man7.org/linux/man-pages/man5/proc_meminfo.5.html) на Linux,
[`GlobalMemoryStatusEx`](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex)
на Windows. На macOS доступная RAM оценивается по свободным и неактивным
страницам. В JSON сохраняется источник оценки. Это снимок перед запуском,
который не учитывает последующий рост потребления памяти другими программами.

## Сравнение отчётов

Скопируйте JSON с машин в одну папку и выполните:

```bash
python3 cpu_bench.py --compare bench_results/*.json
```

Укажите сохранённые файлы (в оболочках с поддержкой wildcard можно использовать
`bench_results/*.json`). Первый файл — база `1.00x`. Значение `2.00x` означает вдвое большую медианную
производительность в соответствующем тесте и режиме. `multi` сравнивает
общую производительность с указанным числом процессов: 24 процесса не
означают 24 физических ядра. Отдельные прогоны `multi` на 12 и 24 процессах
можно сравнить той же командой.

Скрипт проверяет совпадение версии и содержимого скрипта между отчётами,
предупреждает о разных версиях/режимах Python. Если в первом отчёте отсутствует
режим или тест, соответствующая строка сравнения не выводится.

## Методика и статистика

- Пул процессов запускается заранее через `spawn` на всех ОС. Создание
  процессов не входит в замеры; перед каждым заданием процессы синхронизируются.
- Основное время измеряется `perf_counter()`: это фактическая длительность
  выполнения всего арифметического задания, включая передачу задания и возврат результата.
  Для `generate` и `sort` берётся время самой операции внутри рабочего
  процесса: подготовка, проверка и освобождение списка исключены. Полное время
  задания дополнительно записывается в JSON как `end_to_end_seconds`, а область
  замера — как `timing_scope`.
  Отдельно в JSON сохраняется процессорное время каждого рабочего процесса.
- Калибровка и прогрев исключаются из статистики. Порядок тестов циклически
  меняется между повторениями. Сборщик циклического мусора отключён только
  в рабочих процессах; обычное управление памятью Python продолжает работать.
- Результат вычислений проверяется после каждого задания. В JSON остаются
  все измерения, число блоков, число процессов и контрольные результаты.
- В консоли выводятся медиана производительности, медиана/среднее/минимум/
  максимум времени, выборочное стандартное отклонение и CV. CV — отношение
  стандартного отклонения к среднему, в процентах. Порог 5% — практический
  сигнал нестабильности, а не статистическая гарантия точности.
- Медиана — основной показатель. Минимум показывает лучший полученный
  результат, но не заменяет обычную производительность. Выбросы не удаляются.

Подключите ноутбук к питанию, задайте сопоставимые режимы производительности,
закройте тяжёлые программы и дождитесь завершения обновлений. На Apple Silicon
используйте нативный ARM64 Python; архитектура интерпретатора записана в отчёт.
Процессы не закрепляются за ядрами: на неоднородных CPU их размещение решает ОС.
Один процесс поэтому не гарантирует выполнение на конкретном типе ядра.

Для важных выводов проведите 2–3 полных прогона с отдельными файлами. Пять
повторений внутри одного пула не учитывают всю вариативность между запусками
ОС/интерпретатора. Если различия сопоставимы с разбросом, оснований уверенно
объявлять победителя мало. Режимы выполняются последовательно, поэтому
нагрев/турбочастоты также могут влиять на сравнение `single` и `multi`.

Методика опирается на принципы прогрева, калибровки и повторений из
[pyperf](https://pyperf.readthedocs.io/en/stable/run_benchmark.html).
Свойства таймеров описаны в [документации Python](https://docs.python.org/3/library/time.html).
Скрипт не заменяет полноценный набор pyperf/pyperformance. После добавления
списков версия набора и формата отчётов увеличена до 2; отчёты старой версии
не сравниваются с новыми — запустите обновлённый скрипт на всех машинах.

Проверка самого скрипта:

```bash
python3 -m unittest -v test_cpu_bench.py
```
